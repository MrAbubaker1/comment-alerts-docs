Comment Alerts for Jira

Email the assignee and reporter the moment someone comments on an issue.

What it does

When someone comments on a Jira issue, Comment Alerts emails that issue’s assignee and reporter. The message goes out through your own email account, using wording you control, and every attempt is recorded so an administrator can see exactly what was sent.

What this version does not do

It ships with a single rule: new comment → assignee and reporter → every project. There are no per-project rules, no other trigger events, and no recipient picker yet. If one of those is what you need, get in touch — what people ask for is what decides the next release.

Setting it up

You need a Resend account. The free tier is enough to evaluate the app. Step 2 is the one that catches people out, so do not skip it.

  1. Create a Resend account

    Sign up at resend.com.

  2. Verify your sending domain

    In Resend, open Domains, add the domain you want mail to come from, and add the DNS records it shows you. Wait until it reads as verified before continuing.

  3. Create an API key

    Resend → API Keys → Create. Copy it now — Resend will not show it to you again.

  4. Open the app in Jira

    Settings → Apps → Email notifications. You need to be a Jira administrator.

  5. Enter your From address and key

    Use an address on the domain you verified, such as jira@yourcompany.com. Paste the API key and choose Save settings. The key is encrypted and is never displayed again.

  6. Send yourself a test

    Enter your own address under Send a test. If it arrives, you are finished. The next comment on any issue will notify its assignee and reporter.

Do not skip the domain step

Resend gives new accounts a shared sender on resend.dev. It only delivers to the address that owns the Resend account. Mail to anyone else is accepted and then silently discarded — the app reports success, the delivery log says sent, and nothing arrives.

The app warns you when it sees a resend.dev From address. Verify your own domain and the warning clears.

Writing the message

The subject and body are yours to write. Wrap a placeholder in double braces to insert its value with HTML escaped, or triple braces to insert it raw — use triple braces for comment.body so the commenter’s formatting survives.

PlaceholderValue
issue.keyThe issue key, such as ENG-412
issue.summaryThe issue title
issue.descriptionThe issue description
issue.statusStatus name, such as In Progress
issue.priorityPriority name
issue.projectProject name
issue.assigneeAssignee display name, or Unassigned
issue.reporterReporter display name
issue.urlA link straight to the issue
comment.bodyThe comment, as HTML. Use triple braces.
comment.authorWho wrote the comment
actor.nameWho triggered the event

Use Preview to render your template against a sample issue before anyone receives it. A placeholder with no value renders as nothing and is listed under the preview, so a typo shows up rather than going out silently.

Troubleshooting

The test said “sent” but nothing arrived

Almost always the sending domain. If your From address ends in resend.dev, only the address that owns the Resend account can receive anything. Verify your own domain and use an address on it.

Comments are not producing any email

Open Settings → Apps → Email notifications and check Recent sends. A row reading skipped — no resolvable recipients means neither the assignee nor the reporter has an email address the app can read. An issue with no assignee and no reporter produces nothing.

I cannot find the settings page

It is administrator-only, and it lives in Jira admin settings rather than the main Apps menu: the gear icon → Apps → Email notifications.
